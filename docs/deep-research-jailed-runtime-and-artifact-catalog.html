Deep Research Runtime, Artifact Catalog, and Jail Filesystem

Technical note for the SignalFold AI sidecar. This documents what the artifact catalog means, where files are stored, and how run data is exposed to the Docker jail.

Short answer about the Usage column: the Usage column in the Deep Research artifact catalog is per research job. It is recomputed from that job's frozen scope, events, saved code cells, and final citations when the catalog endpoint is opened. It is not a global pipeline-run counter, and it is not a kernel-level file-access audit.

What The Catalog Represents

Deep Research freezes a whole-run catalog when a proposed plan is approved. That frozen catalog describes every run-relative file the agent may see or fetch, including canonical stage outputs and legacy client-deliverable copies. The catalog is stored inside the job's scope-manifest.json, not rebuilt from whatever the run folder happens to contain later.

The visible Data used dropdown and the Artifact Catalog HTML page are views over that frozen job catalog plus per-job usage signals.

Column / countMeaningSource
available File is in the frozen job catalog, but was not detected as read, cited, fetched, or pre-staged-but-unused for this job. scope.catalog in scope-manifest.json.
read The file path was detected in saved Python code cells under workspace/code. This is a provenance heuristic over the code text, not an OS syscall trace. collectCatalogUsageSignals() scans saved code cells.
fetched The agent explicitly called fetch_input(path), causing that catalog file to be staged into workspace/inputs. agent_fetch_input events.
cited The file backed final findings or evidence in the job outputs. workspace/outputs/findings.json, answer model outputs, and evidence records.
staged but unread The file was copied into the jail's read-only inputs/ warm set, but no usage signal showed that the agent read, cited, or fetched it. Frozen staged artifact list minus read/cited/fetched signals.
Precision boundary: Usage is accurate for tool-mediated fetches and final citations. The read signal is intentionally best-effort because it is derived from saved code text. If code constructs paths dynamically, reads an entire directory, or a library reads a file indirectly, Usage may under-report or simplify the access pattern.

Host Filesystem Layout

The AI sidecar defaults its data root to data/ under the repository. Deployments may override this with SIGNALFOLD_DATA_DIR. Completed pipeline runs live under data/runs/{run_id}.

data/ proteomics.db ai_insights.sqlite runs/ RUN-.../ artifact_index.json artifact_index.html run_manifest.json input/ stage1/ stage2/ stage3/ 03_analysis_.../ ai_insights/ artifacts/ sessions/ work/ evals/ research/ jobs/ research_.../ scope-manifest.json workspace/ inputs/ outputs/ code/ tmp/ artifacts/ step_.../ package/ research-report.html evidence-record.json artifact-index.json computation-manifest.json

Original Run Artifacts

Pipeline outputs are the source of truth and remain in data/runs/{run_id}. Examples include stage1/volcano_results.tsv, stage1/module_assignments.csv, stage2/go_enrichment_all.csv, and legacy deliverable paths such as 03_analysis_CBN_median/....

AI Sidecar Job State

Deep Research job files are stored below data/runs/{run_id}/ai_insights/research/jobs/{job_id}. The database row stores scope_manifest_path relative to ai_insights, so the job can re-open its frozen manifest later.

PathPurpose
scope-manifest.jsonFrozen scope: selected staged artifacts, whole-run catalog, hashes, exclusions, lineage, budget, and approved sources.
workspace/inputsHost-side mirror of files mounted into Docker at /work/inputs. Files are copied from the run folder and chmodded 0444.
workspace/codeSaved Python cells, mounted read-only into Docker at /work/code. File names include a code hash prefix.
workspace/outputsWritable output area mounted into Docker at /work/outputs. Contains findings, activity trace, generated tables, figures, and other cell outputs.
artifacts/step_...Durable per-step copies of generated outputs, registered with the SignalFold artifact sink.
packageFinal report package: research report, evidence record, artifact index, computation manifest, external evidence, rerun descriptor, open questions, and next-step recommendation.

How Files Enter The Jail

A Deep Research job starts with an approved frozen manifest. Before execution, the executor verifies that the manifest hash still matches and that referenced source files still match their approved SHA-256 hashes. The agent never receives a direct mount of data/runs/{run_id}.

  1. The plan is approved and buildResearchScopeManifest(..., withCatalog: true) writes a frozen scope-manifest.json.
  2. The executor creates workspace/inputs, workspace/outputs, workspace/code, and workspace/tmp under the job root.
  3. Each selected warm input in scope.artifacts is read from data/runs/{run_id}/{artifact.path}, hash-checked, copied into workspace/inputs/{artifact.path}, and chmodded 0444.
  4. The agent may later call fetch_input(path). That path must be in the frozen whole-run catalog, must resolve inside the run folder, must still exist, and must match the approved hash before it is copied into workspace/inputs.
  5. Python cells and offline skill scripts are executed with CWD /work, reading inputs/... and writing outputs/....

Docker Jail Boundary

The free-form investigation plane launches a per-job Docker container from signalfold-freeform-jail:1.1 by default. The image is built from ai-sidecar/docker/freeform-jail.Dockerfile. 

docker run -d --rm --name sf-ff-...
  --label signalfold.freeform=1
  --label signalfold.job={job_id}
  --network none
  --memory {FREEFORM_JAIL_MEMORY}
  --cpus {FREEFORM_JAIL_CPUS}
  --pids-limit {FREEFORM_JAIL_PIDS}
  --read-only
  --tmpfs /tmp:rw,size={FREEFORM_JAIL_TMPFS},mode=1777
  --security-opt no-new-privileges
  --init
  -v {job}/workspace/inputs:/work/inputs:ro
  -v {job}/workspace/outputs:/work/outputs:rw
  -v {job}/workspace/code:/work/code:ro
  -w /work
  signalfold-freeform-jail:1.1 sleep infinity
ConstraintEffect
--network noneNo network interface for run_python or offline skill execution.
--read-onlyThe image root filesystem cannot be modified.
--tmpfs /tmpTemporary writes are allowed only in an ephemeral, size-limited tmpfs.
/work/inputs:roFrozen run inputs are readable but not writable in the container.
/work/code:roCode cells are written by the host sidecar, then mounted read-only into the container.
/work/outputs:rwThe only persistent writable path visible to jailed code.
no-new-privilegesPrevents privilege escalation through setuid-style paths.
Memory, CPU, PID limitsResource use is bounded by config values such as FREEFORM_JAIL_MEMORY, FREEFORM_JAIL_CPUS, and FREEFORM_JAIL_PIDS.

What The Container Does Not See

  • It does not see the repository checkout.
  • It does not see the whole data/runs/{run_id} folder.
  • It does not see other runs.
  • It does not see ai_insights.sqlite or proteomics.db.
  • It does not receive API keys as container environment variables for offline jailed code.
  • It does not have network access in the sealed free-form/offline-skill path.

Offline Skills

Offline scientific skills are baked into the image under /opt/skills/scientific. They run inside the same sealed container as run_python. Their scripts are resolved within the named skill folder, arguments cannot be absolute or traversing paths, and outputs are attributed by diffing outputs/ before and after execution.

Phone-home *_ai.py scripts are removed at image build time, so they are absent from the sealed jail rather than merely blocked at runtime.

Network Skills And External Lookups

The sealed free-form jail is offline. Curated external corroboration through request_external runs in the Node control plane with source allowlists, cost accounting, and audit records. Separately reviewed network skills, when enabled by deployment configuration, use a different egress-proxied container path, not the sealed --network none jail.

Why Usage Can Change Between Jobs

The frozen catalog belongs to a specific research job. If you run a new Deep Research job against the same pipeline run, it freezes its own scope and produces its own usage signals. Therefore two jobs on RUN-E2E-VERIFY can show the same available files but different read, fetched, cited, and staged but unread status.

Within one completed job, opening the catalog recomputes the view from durable job artifacts and events, but the result should be stable unless the job is still running, has been resumed, or its persisted records are changed by a retry/extension path.

Operational Pointers

  • Build the sealed jail image with ai-sidecar/run.sh jail-build.
  • If Docker is unavailable or the jail image is missing, free-form research fails closed; it does not fall back to host subprocess execution.
  • Generated code cells are available under workspace/code; final findings and traces are under workspace/outputs; packaged human-readable outputs are under package.
  • The artifact catalog HTML route is /api/research/jobs/{job_id}/catalog.html.
