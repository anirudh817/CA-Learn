A Deep Research job today computes real evidence and then fails to say what it means. This spec adds the missing final phase: a per-workflow synthesis skill that reads the actual computed outputs, decides the answer deterministically, and (when permitted) narrates it with an LLM under strict anti-fabrication guards.

1 · The problem

Why this exists

A completed job runs three deterministic skills, then buildPackage() (service.ts:338) emits eight templated files plus the computed artifacts — about twelve deliverables. Two of those slots are supposed to answer the question; both are stubs:

  • claim.text is a fixed string — "{workflow} completed against the frozen run scope" (service.ts:346). It never states a finding.
  • decision-summary.txt interpolates counts ("N artifacts and M computations", service.ts:357), not the result.
  • reportHtml() (service.ts:372) reports scope.artifacts.length and computations.length — it never opens threshold-sensitivity.csv.
  • The verdict is computations.length ? "differentiated" : "standard-equivalent" (service.ts:350) — a "did anything run" flag, not a scientific answer.
  • The UI lists all twelve files as equal-weight download links (app.js:683). No answer is surfaced.

The literal answer is already on disk, unread: runStability writes features_passing per threshold (runner.ts:141); runEda writes row/column/missingness (runner.ts:129); runPathway writes ranked terms (runner.ts:153). Nothing reads them back and says what they mean.

2 · Goal & success criteria

Definition of done

A completed run must produce a coherent synthesis that (a) answers the original objective bottom-line-up-front, (b) weaves pipeline evidence + new computation into a readable narrative, (c) is honest about limitations, and (d) is the primary deliverable — a prominent inline answer panel + a genuinely readable HTML report — with raw artifacts demoted to supporting evidence beneath.

3 · Core principle — deterministic spine, optional narrator

The one idea

Synthesis splits into two layers with a hard boundary:

  1. Interpreter / decide() — pure code, offline. Reads the computed outputs, derives the verdict and the numbers, assembles a structured AnswerModel. This is the source of truth and what rerun reproduces bit-for-bit. This alone fixes the problem even with zero LLM.
  2. Narrator / narrate() — optional LLM, gated. Takes the AnswerModel — numbers and citations already decided — and writes readable prose. It never picks the verdict and never sources a number. Labeled model-generated, provenance-stamped, and validated against the spine before it ships.

The trust property: the LLM cannot fabricate because it is not the one deciding anything factual. It is a phrasing engine over a frozen fact set. That is what makes a non-deterministic component safe inside a "deterministic, reproducible" product.

Determinism & provenance stance

LayerDeterministic?Reproducible?Provenance
Computations, hashes, scope manifest✅✅ bit-for-bitalready recorded (ComputationRecord)
Interpreter verdict + metrics (decide())✅✅ bit-for-bitderived from hashed inputs; in evidence record
LLM narrative prose (narrate())❌❌ — auditable, not reproduciblemodel id + prompt SHA + output SHA + guard result in computation-manifest

The honest one-liner: numbers reproducible; phrasing attributable. A job always completes offline. If there is no key, the cost cap is 0, or the LLM/guard fails, it ships deterministic prose. rerun reproduces the spine exactly and re-narrates (prose may differ; the answer cannot).

6 · The AnswerModel

The one shape everything renders

// src/research/synthesis/types.ts
export interface AnswerMetric {
  label: string;                 // "features passing at adj-p ≤ 0.05"
  value: string | number;        // 2
  cite: { path: string; rowIds?: Array<number | string> };  // stage1/volcano_results.tsv
}

export type VerdictLabel =
  | "stable" | "threshold-sensitive" | "sample-driven"
  | "context-dependent" | "insufficient-evidence";       // §8 plain tags, no GRADE

export interface AnswerModel {
  schemaVersion: "1.0";
  objective: string;
  workflowId: string;
  verdictLabel: VerdictLabel;                  // the scientific answer
  marginalValue: "differentiated" | "standard-equivalent";  // existing gate, kept
  headline: string;            // deterministic BLUF one-liner
  summary: string;             // 2–4 sentence deterministic synopsis (spine's own words)
  metrics: AnswerMetric[];     // every number with provenance
  pipelineFacts: Array<{ path: string; family: string; sha256: string;
                         rowIds: Array<number|string>; configRefs: string[] }>;
  computationFacts: Array<{ skillId: string; entrypoint: string;
                          params: Record<string,unknown>; seed: number|null;
                          outputs: string[]; deterministicRerun: string }>;
  decisionImplication: string;
  limitations: string[];
  chart?: { kind: "sweep"; xLabel: string; yLabel: string;
            series: Array<{ label: string; value: number }> };  // data for the real figure
  narrative?: {
    text: string;
    generatedBy: "model" | "deterministic";
    model?: string; promptSha?: string; outputSha?: string;
    costUsd?: number; guard?: "passed" | "rejected" | "skipped";
  };
}

headline, summary, metrics, chart, and verdictLabel are produced only by decide() (deterministic). narrative is produced by narrate() and is the only model-touched field.

7 · Verdict derivation — finding-stress-test

The decisions, made in code

decide() reads threshold-sensitivity.csv (from the stage1-finding-stability computation) into (threshold → count), sorted ascending. With counts c[0..n-1]:

ConditionverdictLabel
all counts == 0insufficient-evidence
c[0] === c[n-1] and c[0] > 0 (count constant across the range)stable
count varies across thresholdsthreshold-sensitive
sample-driven reserved until leave-one-out influence is computed; context-dependent reserved for the external (curated) arm. Both are out of scope here but in the enum so the report vocabulary is stable.

It also computes a per-feature note: if a feature named in the objective (or the top feature) survives every threshold, say so even when the overall set is threshold-sensitive — that nuance is the useful answer.

Worked example (the test fixture). APOE adj-p 0.002, CLU 0.04, APP 0.5 at thresholds [0.01, 0.05, 0.1] → counts [1, 2, 2]. c[0]=1 ≠ c[2]=2 → threshold-sensitive.
Headline: "Threshold-sensitive: 1→2 features pass as the cutoff loosens from 0.01 to 0.1. APOE clears every cutoff; CLU enters only at adj-p ≤ 0.05."
Metrics: features_passing@0.01 = 1, @0.05 = 2, @0.1 = 2 — each citing stage1/volcano_results.tsv rows. Chart: a 3-bar sweep of those counts.

8 · The synthesis skill contract

One per workflow

// src/research/synthesis/types.ts
export interface SynthesisContext {
  job: { id: string; runId: string; workflowId: string; objective: string;
         budgetUsd: number; model: string };
  scope: ResearchScopeManifest;          // frozen artifacts + configs + hashes + sources
  computations: ComputationRecord[];     // prior offline steps (skillId, params, output paths, sha256)
  readOutput: (relPath: string) => string;  // safe read under {jobRoot}/artifacts (path-escape guarded)
}

export interface SynthesisSkill {
  id: string;                 // "finding-stress-test-synthesis"
  workflowId: string;         // "finding-stress-test"
  version: string;            // semver, mirrored in the manifest
  reads: { computations: string[]; families: string[] };   // declared inputs, validated before decide()
  decide(ctx: SynthesisContext): AnswerModel;              // DETERMINISTIC — verdict, metrics, headline, chart
  prompt(answer: AnswerModel): { system: string; user: string };  // workflow-tailored narrator prompt
  fallbackProse(answer: AnswerModel): string;             // deterministic prose when the LLM is off/guarded
}

The shared system prompt reuses DEEP_RESEARCH_SYNTHESIS_POLICY (evidence.ts:19) + the ready-made §9 card-generation prompt; each skill's prompt() appends only the workflow-specific framing and the AnswerModel facts as the user turn. finding-stress-test is implemented; other workflows register a stub that throws NotImplemented at decide() — caught by the engine and surfaced as a clean "synthesis pending for this workflow" rather than a job failure.

9 · The synthesis engine

Shared: LLM + guard + provenance

// src/research/synthesis/engine.ts
async function runSynthesis(ctx): Promise<AnswerModel> {
  const skill = registry[ctx.job.workflowId];
  if (!skill) return null;                       // no synthesis for this workflow → engine no-ops
  assertReads(skill.reads, ctx);                 // declared inputs present + hashes match scope
  const answer = skill.decide(ctx);              // deterministic; ALWAYS produced
  answer.narrative = await narrate(skill, answer, ctx);   // gated; NEVER throws
  return answer;
}

async function narrate(skill, answer, ctx) {
  const cap = remainingCap(ctx.job);             // §14 cost-cap coordination
  if (!narratorConfigured(ctx) || estCost(answer) > cap)
    return { text: skill.fallbackProse(answer), generatedBy: "deterministic", guard: "skipped" };
  try {
    const { system, user } = skill.prompt(answer);
    const raw  = await narrator.complete({ system, user, model: pickModel(ctx) }); // no tools, no skills
    const prose = scrubOutput(raw.text);                         // security.ts
    const v = validateSynthesisAgainstEvidence(prose, answer);   // NEW guard
    if (!v.ok) return { text: skill.fallbackProse(answer), generatedBy: "deterministic", guard: "rejected" };
    return { text: prose, generatedBy: "model", model: raw.model,
             promptSha: sha(system + user), outputSha: sha(prose), costUsd: raw.costUsd, guard: "passed" };
  } catch {
    return { text: skill.fallbackProse(answer), generatedBy: "deterministic", guard: "skipped" };
  }
}

narrator.complete() is the one-shot LLM helper (new, src/research/synthesis/narrator.ts). It mirrors the proven session setup in sessionFor() (runtime.ts:333) — AuthStorage → ModelRegistry → createAgentSession with tools: [] and an empty skills override → session.prompt() → accumulate text_delta → return. pickModel() resolves Claude-if-keyed-else-job-model via keyResolver + models.resolve.

Spike (1 of 1). Confirm whether @earendil-works/pi-ai exposes a lighter non-session completion. If yes, use it; if not, the createAgentSession path above is the safe reuse. Either way the helper's signature is unchanged.

10 · Anti-fabrication & trust

Why the prose can be trusted

  • No tools, no skills, no private data beyond the AnswerModel. The narrator session is created with tools: [] and an empty skills override — the lethal trifecta is broken by construction.
  • Output scrubbing. scrubOutput() (security.ts) on the prose before storage/render, identical to the chat path (runtime.ts:200).
  • New numeric + citation guard. validateSynthesisAgainstEvidence(prose, answer): every number-like token in the prose must appear in answer.metrics (within tolerance), and every cited path must be in scope.artifacts. Any violation → discard prose, fall back to deterministic, record guard:"rejected". Cheap, deterministic, and makes fabrication structurally unable to reach the user.
  • Labeled in the UI and report whenever generatedBy === "model", with the model id shown.
  • Provenance recorded in computation-manifest.json and a synthesis_completed event: model, promptSha, outputSha, costUsd, guard result.

14 · Cost-cap coordination

First real token spend in research

Compute skills cost $0; synthesis is the first priced operation. Gate it:

  • narrate() runs the LLM only if a key exists and estCost(answer) ≤ remainingCap, where the cap is job.budgetUsd / scope.budget.maxCostUsd (research-scope.ts:108, default 1.25; workflow defaultBudgetUsd is 0 today → deterministic-only until a budget is set).
  • estCost = model.promptCost/completionCost (models.ts) × token estimate of {system,user} + a max-output allowance.
  • Actual cost is recorded in spend_usd and in the synthesis provenance.

Coordinate with the pass-2 cap work. This consumes the cap; it must not re-implement it. If the cap API changes shape, remainingCap() is the single integration point.

17 · Scope & future

Honest boundary

  • In scope now: the synthesis layer (interpreter + gated narrator + guard), the network-policy widening, the answer panel + narrative report + real chart, and the finding-stress-test synthesis skill.
  • Next workflows: each adds one SynthesisSkill file (decide() + prompt()) + a manifest. ranked-pathway-investigation is the natural second (headline = top ORA term + FDR + count below 0.05).
  • External corroboration (curated policy): the third arm — UniProt/Reactome/STRING/PubMed bound to rows, behind the external_lookups safety chain. Unlocks context-dependent verdicts and interpretation/hypothesis claim types. Deferred.
  • Not now: leave-one-out (sample-driven), RO-Crate export, multi-agent fan-out, isolation backend.
