1. Recommendation in one page

Build one AI Insights product surface on one Pi sidecar runtime. Every current AI capability is ported into that runtime. Standard is the default policy profile; Deep Research is an expanded policy profile on the same Pi session, security, grounding, persistence, provenance, artifact, feedback/notes, credential, and cost infrastructure. There is no Python “standard engine” beside Pi and no separate Deep Research backend path.

  1. Standalone first, embeddable later confirmed 2026-06

    The sidecar serves a full-page AI application for development and manual testing, with a completed-run selector and new-browser-tab workflow. Later, the same AIInsightsApp.mount() component embeds inside SignalFold’s results tab; there is never a second chat implementation.

  2. One canonical Node/Pi sidecar confirmed 2026-06

    The sidecar owns all AI behavior, including Standard and Deep Research. FastAPI may later issue run-access capabilities or reverse-proxy transport for embedding, but it does not retain an AI engine, provider path, security implementation, or persistence path.

  3. Conversation defaults, per-turn source snapshots proposed 2026-06

    Data-source selection should be convenient at conversation scope but overridable on each turn. The effective set is persisted on the message, so every answer is reproducible and auditable.

  4. No committed secrets non-negotiable

    The OpenRouter key is accepted through the encrypted BYOK UI or a local .env fallback. The repository receives only a blank template. “Put the key here for now” must not become a checked-in credential.

  5. Foundations apply to every policy confirmed 2026-06

    Security, streaming isolation, attachments, credentials, provenance, costs, errors, and regression evaluation are sidecar foundations—not optional Standard or Deep Research features. In particular, AI-PRES-014 wraps every turn, tool result, generated artifact, and model policy.

  6. Cut over, migrate, then delete the old implementation proposed 2026-06

    The old routes/modules are removed only after data migration, parity, and rollback verification. There will be no parallel legacy chat, Python provider engine, unused DOM shell, dead provider code, or abandoned database columns after the cutover.

5. Target architecture

The current backend already stores provider/model/token/cost fields per answer at backend/database.py:294 and applies a bounded four-round tool loop at backend/routes/conversations.py:1470. Those behaviors are ported into sidecar foundations. Standard and Deep Research then select different RuntimePolicyProfile values on the same Pi session registry; neither policy bypasses security, persistence, provenance, credentials, costs, or run authorization.

Why the sidecar becomes the whole AI backend

K-Dense creates persistent Pi sessions using createAgentSession() and DefaultResourceLoader at ../k-dense-byok/server/src/agent/session-registry.ts:90. Rather than retain today’s Python chat engine and bolt Pi beside it, the port moves the full AI subsystem into the TypeScript sidecar. SignalFold’s FastAPI/pipeline stack remains intact, but its future AI integration is limited to transport and signed run-access capabilities.

In standalone developer mode the server binds to 127.0.0.1, serves the UI, and uses a read-only filesystem run adapter. In embedded mode it accepts a short-lived SignalFold capability proving user/workspace/run access. Both hosts invoke this same API; only the transport/auth adapter changes.

Dependency policy

Start from the exact locally-proven K-Dense set—@earendil-works/pi-ai, pi-agent-core, and pi-coding-agent at 0.79.0—and pin exact versions plus lockfile for the first implementation. K-Dense’s lock requires Node ≥22.19.0. Upgrade only in a dedicated dependency PR after contract tests.

Credential isolation

K-Dense uses a process-global OpenRouter key at ../k-dense-byok/server/src/agent/models.ts:117. SignalFold cannot copy that assumption because it has users, workspaces, BYOK precedence, and encrypted keys. Credential storage and resolution are ported into sidecar foundations; each user/session receives isolated AuthStorage. A one-time migration imports existing encrypted Anthropic settings. Keys remain memory-only during execution and are excluded from JSONL, traces, errors, artifacts, and child-process environments.

9. External data-source selection

Recommendation: conversation default + per-turn override. Conversation-only selection is convenient but makes historical turns ambiguous after a setting changes. Turn-only selection is reproducible but tedious. The hybrid provides both.
  • Conversation: default allowed sources, e.g. UniProt + PubMed.
  • Turn: chips can inherit, add, or suppress sources for this request.
  • Persisted snapshot: each user message stores requested_sources, effective_sources, policy decision, and consent version.
  • Provenance: assistant messages store actual source calls and references independently of what was merely allowed.
  • Policy: workspace deny always wins; developer mode never bypasses it.

Phase 1 exposes the four existing biology adapters only. Arbitrary Pi web access and MCP connectors are separate capabilities because they materially change the exfiltration boundary.

10. Context, Artifacts, feedback, and Notes

Context vs Artifacts

Context is input selected for reasoning: immutable run outputs, uploads, other authorized runs, and pins. Artifacts are outputs generated by AI or the user’s notes: PDFs, pictures, plots, tables, code, notebooks, eval reports, and the notes ledger. Generated files never mingle with stage1/2/3 pipeline files.

Per-answer controls

Place thumbs-up, thumbs-down, and a Notes icon under every completed assistant answer (not only at conversation end). A note save creates a database feedback row and appends a human-readable entry to the run’s notes artifact with timestamp, user, conversation/message IDs, query, answer snapshot/hash, rating, and note. Editing a note appends a revision rather than rewriting history.

Durability

The Artifacts rail is run-scoped and therefore shared across every conversation on that run. Deleting a conversation does not delete generated artifacts by default; explicit artifact deletion is audited. Conversation exports link to artifact IDs and checksums.

12. Skills and Python execution

Skill plug-in contract

  1. Catalog — install approved skills under a versioned runtime catalog; do not clone arbitrary repositories during a user turn.
  2. Activation — Pi’s resource loader discovers SKILL.md; the turn records name, version/hash, selection reason, and requested tools.
  3. Policy — SignalFold maps each skill to permitted tools, network policy, input artifact families, output MIME types, timeout, and cost ceiling.
  4. Execution — approved Python runs in the conversation work directory, receives explicit input paths, and may write only registered outputs.
  5. Grounding — developer-mode SSE shows skill_start/end, python_start/end, sanitized command/script path, inputs, outputs, exit code, duration, and resulting artifact IDs.
Security boundary: a cwd is not a sandbox. K-Dense’s local file/shell tools are suitable for a trusted local researcher but do not enforce SignalFold’s multi-user boundary. Python execution is enabled by default as developer-local and is fully traced — every run emits python_start/end with the sanitized command/script path, inputs, outputs, exit code, duration, and resulting artifact IDs, so it is never silent. What is gated is the trust tier, not execution itself: untrusted, multi-user, or production enablement must run on the isolated backend (container/VM or another reviewed confinement mechanism) with no inherited secrets, network deny-by-default, resource limits, and path-mount tests. disabled remains available for locked-down deployments but is not the default.

13. Three-model eval overlay

Scorer function

score_answer(case, answer, evidence) -> {
  grounding: 0..1, citation_correctness: 0..1,
  required_fact_recall: 0..1, safety: 0..1,
  completeness: 0..1, clarity: 0..1,
  latency_ms, cost_usd, weighted_total
}

Grounding, citation existence, forbidden claims, required facts, latency, and cost are deterministic. Completeness/clarity may use a blind judge. The scorer sees candidate labels A/B/C—not model names—and the same frozen run snapshot. The synthesizer receives all candidates plus evidence, must preserve citations, and is scored by the same function. Judge model, prompt version, rubric version, and cost are persisted.

Initial scope: infrastructure evaluation, not Tier-1 comparison

Real Tier-1 scientist-profile and executable-skill comparisons are explicitly deferred. The initial overlay uses the seven standalone fixtures above to prove that three candidates, synthesis, scoring, grounding, script execution, artifacts, costs, and logs are consistent on the one Pi runtime. The repository’s Tier-1 profiles/skills may inform fixture wording, but they are not imported as production content in this milestone.

Store Standard-policy and Deep-Research-policy output, prompt/config hashes, selected sources, tool/skill trace, artifacts, scorer results, and cost under the run’s evals/ directory for future regression work.

15. Migration and “no vestiges” definition

“No vestiges” should be an executable exit gate, not an aesthetic promise.

  1. Inventory — freeze the old file/route/DOM/table/setting list and add a removal test.
  2. Migrate — transactionally copy/reshape conversations, messages, attachments, settings, citations, costs, and pins; verify counts and sampled hashes.
  3. Dual-read only — during one short migration phase, the sidecar migration adapter may read old rows; never dual-write and never route live turns back to Python.
  4. Cut UI atomically — replace the embedded shell with the launcher and standalone implementation in the same commit.
  5. Delete — remove old frontend/modules/chat.js, chatStreams.js, old AI DOM/CSS, old chat routes/services/provider catalog, and superseded tests after equivalent contract coverage points to v2.
  6. Drop obsolete schema — remove migrated tables/columns and migration-only adapters; retain only the generic migration ledger.
  7. Prove absence — rg denylist for old symbols/routes/IDs, OpenAPI snapshot, database schema snapshot, unused-import check, full suite, and browser smoke.
Rollback: create a database and run-directory backup before schema cutover. Rollback restores the backup and turns AI_INSIGHTS_V2=0 back on only until the final vestige-removal release is accepted; after that release, rollback is by Git revert + backup restore, not by keeping dead runtime code.

External data sourcespartialWeb (Exa/Perplexity) and MCP exist; the four biology adapters (UniProt/Reactome/STRING/PubMed) and the dispatcher safety chain (cache → cap → quota → breaker → retry) are absent. Decide TS reimplementation vs Python call-back.
Evaluation / scoring overlayabsentNo eval harness exists. Build the three-model overlay, deterministic scorer, and blind judges from scratch.
FrontendpresentK-Dense is a Next.js/React SPA — a mismatch. SignalFold is vanilla-JS, no build step; do not adopt Next.js. Build AIInsightsApp as one mountable vanilla component.
Cross-cutting gap — the language boundary. Retrieval/grounding (retrievers.py, context_builder.py, query_rewriter.py, artifact_index.py), the security gate (security.py), external_lookups/, and attachment extraction (attachments.py) are proven Python, while the sidecar is Node. Most “partial/absent” rows above inherit one unmade decision: reimplement in TypeScript or call back into Python. The plan must make this explicit before phase 2, because it sets the true cost of “the sidecar owns all AI behavior.”
