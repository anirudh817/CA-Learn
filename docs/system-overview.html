SignalFold — System Overview

A self-hosted FastAPI platform that productionizes an R proteomics pipeline (normalization → WGCNA modules → GO enrichment → cell-type deconvolution) and layers an AI Biological Inference Chat on top, so scientists can converse with a run's own data. Single Python process, vanilla-JS SPA, SQLite, R-as-subprocess. Built for analysts and bench scientists; not a multi-tenant SaaS and not a general LLM chatbot.

LLM Bootstrap read first

What this is in one line: a FastAPI monolith serving a REST API + vanilla-JS SPA, running a 3-stage proteomics pipeline in a background thread and a retrieval-grounded, security-hardened AI chat over each run's artifacts.

Invariants that must not break

  • All work happens on the ssb1 branch; never commit to main — project rule in CLAUDE.md (Working Branch). Claude Code and Codex share this one branch.
  • Every protected endpoint resolves identity through one dependency — get_current_user at backend/deps.py:12. Session tokens are stored/compared as SHA256 hashes (backend/security.py:43), not signed JWTs; passwords are PBKDF2-HMAC (backend/security.py:14).
  • Stage 1 requires R — there is no pure-Python fallback. run_stage1 raises RuntimeError if Rscript or stage1_parity.R is missing (backend/services/pipeline.py:1778). (CLAUDE.md's "otherwise runs pure Python" note is stale.)
  • Pipeline stages never raise on skip — they call step_callback(..., "skipped"/"complete", 100, reason) and write empty outputs so downstream stages keep going (e.g. backend/services/pipeline_stage2.py:232).
  • The AI chat must never reveal internal methodology, USP, pipeline internals, source code, or model identity. System-prompt Rule 0 at backend/services/ai/context_builder.py:70; enforced by the regex scrubber (security.py:143) and a deterministic fail-CLOSED backstop heuristic_output_leak (security.py:213) that runs independent of the fail-open LLM judges.
  • The agentic tool loop is hard-capped at 4 iterations per turn — MAX_TOOL_ITERATIONS = 4 at backend/routes/conversations.py:1470.
  • Internal-methodology files inside a run dir are unreadable by the chat — config_stage*.json, *.R/*.py/*.sh, *.log, stats_control_audit.json, parity scripts are blocked by _is_internal_artifact (backend/services/ai/tools.py:206) for both read_file_slice and @-mention pins.
  • BYOK API keys are encrypted at rest with Fernet derived from SESSION_SECRET (backend/services/ai/crypto.py:28); decryption fails closed to {} on a rotated/corrupt secret (crypto.py:40).
  • External biology lookups are OFF by default and opt-in, always behind the cache → hourly cap → daily quota → circuit-breaker → timeout chain in backend/services/ai/external_lookups/dispatcher.py:174.
  • Pipeline-owned files are off-limits to AI edits — pipeline.py, pipeline_runner.py, the stage runners, and r_scripts/ (CLAUDE.md). The DB schema is additive / auto-created — no migration framework (backend/database.py:354).

Entry points

  • Production: uvicorn main:app → app_loader.create_app() → backend/main.py:35 create_app().
  • Dev: python3 -m proteomics_ai.devserver — auto-selects a free port from 8000 (proteomics_ai/devserver.py:16).
  • UI: frontend/index.html + frontend/app.js (global STATE at app.js:40; chat in frontend/modules/chat.js).
  • Tests: INLINE_RUNS=1 python3 -m unittest discover -s tests (44 files); Playwright e2e in tests/e2e/; node unit test tests/chatStreams.test.mjs.

Non-goals (deliberately out of scope)

  • Multi-provider LLMs (OpenAI/Google) — Anthropic-only; the abstraction is kept provider-shaped but unimplemented.
  • A task queue / distributed workers — one background daemon thread per run; INLINE_RUNS=1 makes it synchronous for tests.
  • A frontend build step — no bundler, no transpile; ES modules loaded directly.
  • A migration framework — schema is additive and auto-created on boot.

What It Does — User Perspective

SignalFold turns a raw proteomics export (PEAKS / Spectronaut / generic abundance matrix) into a client-grade deliverable bundle that matches the Eisai Spec-Pep format — normalization, differential expression, WGCNA co-expression modules, GO enrichment, and cell-type deconvolution — without the analyst touching R. Once a run completes, a scientist opens an AI chat scoped to that run and asks biological questions in plain language; answers are grounded in the run's own tables, cite their sources, track token cost, and refuse to disclose how the platform works.

  • Upload a dataset; the format detector sniffs family/assay-level and recommends parameters.
  • Configure stats controls (DE method, WGCNA power/TOM, GO background, cell-type reference) and launch a run; watch live progress over SSE.
  • Review and remove outlier samples at a mid-run checkpoint before the network is built.
  • Browse interactive results (volcano table, modules, GO, cell types) and download the packaged deliverable bundle.
  • Chat with the run: look up a protein or module, join cell-types to GO, attach a PDF/xlsx, pull opt-in external biology (UniProt/Reactome/STRING/PubMed), pin context, and export the transcript.
  • Bring your own Anthropic key (encrypted at rest) or use a platform key under a daily quota.

Architecture Overview

The defining choice is a single-process monolith with filesystem-as-interface. The pipeline writes everything to data/runs/{run_id}/; the AI chat treats that directory as a read-only black box and never imports pipeline code. That boundary is what lets the chat subsystem evolve (retrieval, security, external lookups) without risking the parity-validated science, and it is reinforced by the rule that pipeline files are off-limits to AI edits. State is split cleanly: SQLite holds metadata and conversations (relational, queryable), while bulk scientific output lives on disk (large CSV/TSV/PDF, streamed not parsed). There is no message broker and no worker pool — concurrency is a daemon thread per run plus async SSE generators.

Data Flow

1 · Pipeline run

A POST /api/runs (routes/runs.py:89) creates a Run row and either runs inline (INLINE_RUNS) or spawns a daemon thread. run_full_pipeline builds the canonical bundle, then pauses at the outlier checkpoint: the worker flips the run to AWAITING_REVIEW and blocks on a threading.Event until POST /review-outliers sets it. Stage 1 shells out to stage1_parity.R for normalization + DE + WGCNA; Stages 2 and 3 are pure Python. Each stage writes config_stageN.json for reproducibility and emits empty files rather than raising on skip.

2 · AI chat turn

send_message (conversations.py:1047) runs input through the rate limiter and regex blocker before any model call, assembles a per-turn context, then enters a tool loop capped at MAX_TOOL_ITERATIONS = 4. Tools read the run's tables (never internal files). Every streamed fragment is scrubbed and checked by the deterministic heuristic_output_leak backstop, which runs even if the fail-open Haiku judges error — so a judge outage can't slip a leak through. The response streams back as SSE.

3 · Hybrid retrieval

Instead of a vector DB, retrieval is schema-aware. query_rewriter infers a QueryIntent (heuristic, optionally refined by one Haiku call); retrieve() (retrievers.py:637) routes that intent to family-specific retrievers keyed off FAMILY_SIGNATURES (column fingerprints, not filenames), so it survives pipeline naming variants. Candidates are reranked by entity/family overlap, then cut to a token budget — and when history exceeds 70% of the input budget, summarize_history compresses older turns while keeping recent ones verbatim.

4 · Anti-exfiltration gate chain

The chat's hard requirement — never reveal methodology, USP, internals, source, or model identity — is enforced as layered gates, not a single prompt. Input passes a rolling rate limiter and a regex extraction blocker; an optional Haiku judge classifies intent (fail-open). The model can only read run data (internal files blocked). Output is regex-scrubbed, then run through the fail-CLOSED heuristic_output_leak, then an output judge. A confirmed leak is persisted as a redacted message. The same gates apply to streaming, non-streaming, and regenerate paths.

Key Design Decisions

  1. FastAPI monolith + vanilla-JS SPA, no build step established 2026-04

    One process serves /api/* and the SPA (backend/main.py); the frontend is hand-written ES modules with no bundler. This keeps the deployment surface to a single container and makes the SPA trivially inspectable, at the cost of manual DOM work and no type-checking on the client.

  2. Background daemon thread instead of a task queue established 2026-04

    Runs execute on a per-run threading.Thread(daemon=True) (pipeline.py:2127); SSE polls the Run.log column. No Celery/RQ/broker. INLINE_RUNS=1 makes runs synchronous so tests stay deterministic. Trade-off: no horizontal scaling of pipeline work, but radically simpler ops for a single-tenant analytical tool.

  3. R subprocess for Stage 1 parity established 2026-04

    Normalization + DE + WGCNA run through stage1_parity.R (bicor/dynamicTreeCut/limma) to match the Eisai reference exactly. The current code requires R and raises if it is absent (pipeline.py:1778) — chosen because byte-for-byte scientific parity beat a maintainable second implementation.

  4. Anthropic-only, but provider-shaped established 2026-05

    Multi-provider was explicitly dropped. The Provider Protocol, catalog, and dispatcher keep a provider-shaped seam so OpenAI/Google could be added mechanically, but only anthropic_provider.py exists and the UI rejects non-Anthropic keys.

  5. Schema-aware retrieval instead of embeddings established 2026-06

    Rather than chunk + embed a vector store, retrieval routes a parsed intent to typed retrievers that slice the run's tables by column signature (FAMILY_SIGNATURES). This grounds answers in exact rows, needs no embedding infra, and tolerates filename drift across pipeline variants.

  6. Defense-in-depth anti-exfiltration with a fail-CLOSED backstop established 2026-06

    The LLM safety judges fail open (a judge outage shouldn't break chat), so a deterministic heuristic_output_leak (security.py:213) fails closed on every answer — closing the gap an adversarial audit found where a judge outage could leak internals. Judges can run on a dedicated key so chat rate-limits can't starve the gate.

  7. BYOK keys encrypted with a key derived from SESSION_SECRET established 2026-05

    User/workspace API keys are Fernet-encrypted at rest (crypto.py:28) using a key derived from the existing SESSION_SECRET, so there is no second secret to manage. Decryption fails closed to an empty dict, so rotating the secret degrades to "re-paste your key" rather than a crash.

  8. Per-conversation stream isolation established 2026-06-18

    Streaming was rebound from global view-state to a per-conversation registry (frontend/modules/chatStreams.js) after a bug let one conversation's tokens bleed into another. The DOM is now a projection of only the on-screen conversation; conversations stream concurrently and independently.

  9. SQLite with additive, auto-created schema established 2026-04

    All models live in one file and are created on boot; a small _migrate_sqlite_schema adds missing columns idempotently (database.py:359). No Alembic. AI-chat tables were added the same way. Trade-off: schema changes must stay additive.

  10. External biology lookups default-OFF behind a safety chain established 2026-06

    UniProt/Reactome/STRING/PubMed are opt-in per conversation and gated by cache → per-conversation hourly cap → per-workspace daily quota → circuit breaker → single-retry timeout (external_lookups/dispatcher.py:174), so a flaky upstream can't stall or balloon a turn.

Key Data Structures

Run (backend/database.py:147) — the central pipeline record. Carries lineage, status, params, and result rollups.

Run(
  id, workspace_id, project_id, created_by,
  file_id -> UploadedDataset, traits_file_id,
  status: RunStatus,            # QUEUED|RUNNING|AWAITING_REVIEW|COMPLETE|FAILED|...
  params: JSON-text,            # stats controls, excluded_samples, ...
  dataset_hash, param_fingerprint,   # used to dedupe identical re-runs
  analysis_format, input_level,
  modules_count, sig_peptides, up_peptides, down_peptides, go_terms,
  log: text, metrics_json, manifest_path, app_version )

Conversation / Message (database.py:274, :294) — the chat domain. A conversation is optionally bound to a run_id (its data scope); messages store provenance, cost, and tool calls.

Conversation( id, run_id?, workspace_id, user_id, provider, model,
  external_lookups_enabled, discovery_mode,           # auto|on|off
  pinned_refs_json, system_prompt_version )
Message( id, conversation_id, role: user|assistant|system|tool,
  content, attachments_json, citations_json, tool_calls_json,
  input_tokens, output_tokens, cost_usd,
  parent_message_id,                # threading for regenerate
  status )                          # complete | redacted | error

artifact_index.json (written by artifacts.py:556) — the on-disk map of a run's outputs the chat reads. Grouped descriptors + display policy; the AI's own artifact_index.py loads this (or falls back to a filesystem scan) and classifies each file via FAMILY_SIGNATURES.

{ "artifacts": [ {family, filename, rel_path, columns, row_count, ...} ],
  "metadata": { run_id, profile, ... },
  "policy":   { "native_first": true, ... } }

QueryIntent / RetrievedChunk (AI retrieval) — the parsed-intent and retrieved-slice shapes that flow query → retriever → reranker → context.

QueryIntent( intent_type, entities[], target_families[],
  requires_cross_modal: bool, confidence, raw_text, notes )
RetrievedChunk( family, source_file, text, score, ... )   # scored + budget-cut

Extension Points

  • New AI tool: add a schema to TOOL_SCHEMAS and a branch in dispatch() (backend/services/ai/tools.py:48). It must read only run data and go through _safe_resolve + _is_internal_artifact, or it becomes an exfiltration hole. Loop budget is governed by the route, not the tool.
  • New retrieval family: add a signature to FAMILY_SIGNATURES (artifact_index.py:45), a retriever fn in retrievers.py, and an entry in _INTENT_DISPATCH. Key off columns, not filenames, so it survives profile variants.
  • New external biology source: implement an adapter (a tool_name + fetch()) and append it to _ADAPTER_LIST (external_lookups/dispatcher.py:48). The cache/quota/breaker/timeout chain wraps it automatically; don't call upstreams directly.
  • New LLM provider: implement the Provider Protocol (providers/base.py:83) — list_models, stream, complete returning the canonical event/usage shapes — add it to the catalog, and teach key_resolver/detect_provider_from_key the key prefix.
  • New pipeline stat control: thread it through the stage config dict and the owning stage; write it into config_stageN.json and the stats_control_audit.json (requested-vs-effective) so reproducibility holds. Add a validation-gate test.
  • New SPA page: add a .page element and route via APP.go(page) (app.js:683); fetch through APP.api()/apiJson() and escape all injected strings with escapeHtml() (app.js:115).

Glossary

artifact index
artifact_index.json — the per-run map of output tables the chat retrieves over.
BYOK
"Bring your own key" — a user-supplied Anthropic API key, encrypted at rest.
canonical bundle
The normalized ETL output (input/cleaned_matrix.csv + manifest) that every stage consumes.
CellTypeFET
Cell-type deconvolution by Fisher's Exact Test against marker sets (Stage 3).
deliverable bundle
The client-formatted output folders (Eisai Spec-Pep layout) packaged after the pipeline.
discovery mode
Per-conversation toggle (auto/on/off) for artifact-grounded biological interpretation.
FAMILY_SIGNATURES
Column-fingerprint definitions used to classify a run's files by data family.
fail-CLOSED / fail-open
A gate that blocks on error (heuristic leak check) vs. one that allows on error (LLM judges).
GO enrichment
Gene-Ontology over-representation via signed FET z-scores with global BH FDR (Stage 2).
hybrid retrieval
Intent-routed, schema-aware table slicing (no embeddings) that grounds chat answers.
outlier review
Mid-run checkpoint where a run waits (AWAITING_REVIEW) for sample-exclusion decisions.
parity
Byte/stat-level agreement of pipeline output with the Eisai R reference.
WGCNA
Weighted gene co-expression network analysis — module detection (bicor + dynamicTreeCut), Stage 1.

End-to-End Use-Case Workflow

  1. Authenticate — client sends a session token (Bearer / X-Session-Token / query); get_current_user (deps.py:12) resolves it by SHA256 lookup. Local dev auto-bootstraps an admin + workspace.
  2. Upload a dataset — POST /api/uploads (routes/upload.py:127) stores the file and an UploadedDataset row; input_detector.detect_input_format (input_detector.py:313) sniffs family/assay-level and recommends params.
  3. Launch a run — POST /api/runs (routes/runs.py:89) creates a Run (QUEUED), dedupes on dataset+param fingerprint, and starts the pipeline (thread, or inline under INLINE_RUNS).
  4. Watch progress — the SPA opens GET /api/runs/{id}/events (runs.py:294), a 0.5s-poll SSE stream of log + stage status.
  5. Review outliers — at the checkpoint the run flips to AWAITING_REVIEW and blocks; POST /api/runs/{id}/review-outliers (runs.py:551) records the decision and unblocks the worker.
  6. Pipeline completes — Stage 1 (R) → Stage 2 → Stage 3 → emit_legacy_bundle (deliverables.py:1520) → write_artifact_index (artifacts.py:556); status → COMPLETE.
  7. Explore + download — results pages render the volcano/modules/GO/cell-type tabs; the deliverable bundle is downloadable as a zip.
  8. Chat with the run — POST /api/runs/{id}/conversations then POST /api/conversations/{id}/messages (conversations.py:1047) streams a grounded, security-gated answer with citations and a cost rollup.
