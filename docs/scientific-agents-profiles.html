1. What the scientific-agents repo is

scientific-agents is a library of 503 "expert-thinking" profiles, one per profession. Each is an AGENTS.md file (mirror CLAUDE.md) that teaches an AI agent to reason like a senior practitioner — the databases and instruments it reaches for, how it frames a problem, how it stress-tests a claim, and the failure modes it treats as first-class. Not a Python package; you install a profile by dropping it into a project as AGENTS.md. Profiles live at scientific-agents/scientific-agents/<slug>/AGENTS.md and are indexed in catalog.json. This document maps the 20 relevant to SignalFold and changes nothing in either repo.

Proteomics Scientist proteomics-scientist Tier 1 · primary 60 sources · 335 lines

bottom-up LC-MS/MS · DDA/DIA/TMT/SILAC · differential abundance · FDR & batch control

The single most relevant profile — it owns the ETL missing-value handling and the stage-1 normalization + differential-abundance logic at the heart of the pipeline.

(a) Skills to include — grounded

  • Classify the missing-value mechanism, then impute by model — MCAR/MAR vs MNAR; prefer left-censored imputation (QRILC/MinDet) over zero/mean fill. proteomics-scientist/AGENTS.md › Rigor And Critical Thinking · L173–176 (also Mindset · L33–34)
  • Name the quantification modality & acquisition mode first — LFQ/SILAC/TMT × DDA/DIA each carry different normalization logic. proteomics-scientist/AGENTS.md › Mindset And First Principles · L16–20, L40
  • Keep peptide- and protein-level inference separate; report picked-protein FDR at 1% — razor/shared peptides make protein abundance a modeled summary. proteomics-scientist/AGENTS.md › Rigor And Critical Thinking · L166–167 (also Mindset · L27–28)
  • Flag TMT ratio compression from co-isolation interference — attenuated fold changes are an artifact. proteomics-scientist/AGENTS.md › How You Frame A Problem · L60 (also Mindset · L32)
  • Treat contaminants as first-class (keratin/BSA/albumin) — contaminant databases are not optional. proteomics-scientist/AGENTS.md › Troubleshooting Playbook · L199, L215 (also Data · L145)

(b) What it enhances

  • Representation: make missingness and acquisition mode explicit in the canonical matrix instead of imputing them away.
  • Interpretation: DE read through the right error model, with fold-change-attenuation and protein-ambiguity caveats.
  • Discovery: recover low-abundance, left-censored proteins (often the signaling biology) that naive pipelines discard.

(c) Prompts for the next pass

c.1 · Explore & investigate

"Walk _build_canonical_bundle() and classify the missing-value mechanism of a sample run (MNAR vs MAR vs MCAR): quantify left-censoring, plot missingness against intensity, and judge whether the current imputation and normalization fit the declared acquisition mode."

c.2 · Critique

"As a proteomics reviewer, critique stage-1 differential abundance: are FDR, normalization, and missing-value handling appropriate for DDA/DIA/TMT? Where are fold changes biased or compressed, and what would Reviewer 2 reject?"

c.3 · Implementation thoughts

"Propose a minimal, backward-compatible way to add MNAR-aware imputation and acquisition-mode-matched normalization as stage-1 params, preserving the empty-output-on-skip contract and the artifact_index schema."

Mass Spectrometrist mass-spectrometrist Tier 1 added 218 lines

clinical / research mass spectrometry · resolution & mass accuracy · quantitation · system suitability

The instrument-level complement to proteomics-scientist — SignalFold is an MS data platform, so the reasoning about what an m/z, a resolution, and a calibration actually license is foundational.

(a) Skills to include — grounded

  • Resolution (R = m/Δm) and mass accuracy (ppm) gate identity — they define ion isolation and formula/peptide assignment; an ID is only as trustworthy as the mass accuracy behind it. mass-spectrometrist/AGENTS.md › Mindset And First Principles · L15 (also L14)
  • Quantitation requires calibration; matrix effects bite — external/internal/isotope-dilution calibration, and ion suppression/matrix effects distort intensities. mass-spectrometrist/AGENTS.md › Mindset And First Principles · L25; How You Work · L60
  • System suitability before biology — instrument qualification, maintenance, and suitability checks decide whether a run is even interpretable. mass-spectrometrist/AGENTS.md › Instrument Qualification, Maintenance, And System Suitability · L161+

(b) What it enhances

  • Representation: attach mass-accuracy / resolution / suitability metadata to runs so identifications carry their own confidence.
  • Interpretation: distinguishes a real abundance change from a calibration/matrix artifact before stage-1 ever runs.
  • Discovery: rescues or rejects borderline identifications on instrument grounds the analyst layers miss.

(c) Prompts for the next pass

c.1 · Explore & investigate

"For a sample run, surface whatever instrument metadata SignalFold ingests (resolution, mass accuracy, calibration, suitability) and assess whether identification and quantitation are defensible on instrument grounds — flag where that metadata is missing entirely."

c.2 · Critique

"As a mass spectrometrist, critique what SignalFold assumes about its input: does it treat intensities as calibrated and matrix-effect-free? Where would ion suppression or a drifting calibration silently corrupt the canonical matrix?"

c.3 · Implementation thoughts

"Propose an optional system-suitability gate at ingest (mass-accuracy / QC-acceptance thresholds) that flags a run as low-confidence in RunStageStatus without blocking the pipeline."

Bioinformatician bioinformatician Tier 1 57 sources · 305 lines

dry-lab / computational genomics

The differential-expression and reproducibility backbone for stages 1–2 and the external-lookup interpretation layer.

(a) Skills to include — grounded

  • Model batch as a design covariate — don't run DESeq2/edgeR/limma on a corrected matrix without inflating significance. bioinformatician/AGENTS.md › Mindset And First Principles · L22–24
  • Keep identifiers stable across tables; MANE/GENCODE-consistent annotation — ID drift silently drops features at each join. bioinformatician/AGENTS.md › How You Frame A Problem · L56; Tools, Instruments, And Software · L120
  • Prove reproducibility, don't assert it — same build, versions, seeds, metadata must reproduce counts/calls. bioinformatician/AGENTS.md › Mindset And First Principles · L40–41 (also How You Work · L84)
  • Report padj (Benjamini–Hochberg FDR), never raw p alone — with effect sizes attached. bioinformatician/AGENTS.md › How You Work · L90 (also Rigor · L176)

(b) What it enhances

  • Representation: a stable, versioned identifier spine making every stage-to-stage join lossless and auditable.
  • Interpretation: DE read with batch modelled, not confounded.
  • Discovery: the compare route becomes trustworthy once references/IDs stop drifting between runs.

(c) Prompts for the next pass

c.1 · Explore & investigate

"Trace one protein identifier from the uploaded matrix through stage-1 DE, stage-2 GO mapping, and the external lookups. Find every point where accession↔symbol↔Ensembl mapping could drop or mismap a feature, and quantify the loss on a real run."

c.2 · Critique

"As a bioinformatician, review stage-1 DE: is batch a model covariate or a correct-then-test step? Are references and IDs version-pinned? Flag anything that would fail an nf-core / reproducibility review."

c.3 · Implementation thoughts

"Propose a versioned identifier-mapping layer — and where it should sit relative to _build_canonical_bundle — that makes stage joins lossless, with an unmapped-feature report surfaced to the run."

Biostatistician biostatistician Tier 1 68 sources · 252 lines

clinical / computational / trial and omics biostatistics

The statistical-rigor layer across all three stages — what is estimated, how multiplicity is controlled, and whether the design is confounded.

(a) Skills to include — grounded

  • Start from the estimand, not the estimator — population, contrast, intercurrent-event handling before fitting. biostatistician/AGENTS.md › Mindset And First Principles · L14–18 (also Frame · L55)
  • Treat Type I error as a portfolio; name the multiplicity family — FWER vs FDR across endpoints/stages. biostatistician/AGENTS.md › How You Frame A Problem · L59 (also Mindset · L20)
  • Check batch confounding & the experimental unit — is condition aliased with batch; is the unit the patient/tumor, not the well? biostatistician/AGENTS.md › intro · L6–7; How You Frame A Problem · L56
  • Model correlation honestly with MMRM / mixed models — repeated/nested designs need random effects. biostatistician/AGENTS.md › Mindset And First Principles · L28; How You Work · L85

(b) What it enhances

  • Representation: an explicit design model (conditions, batches, replicates, unit) the stats engine can read.
  • Interpretation: p-values/FDR at the correct family level, with effect sizes and CIs — not p alone.
  • Discovery: fewer false leads and more reproducible hits — discovery you can defend.

(c) Prompts for the next pass

c.1 · Explore & investigate

"Audit the full hypothesis-testing surface of a run: enumerate every test across stages 1–3, the multiplicity correction at each, the experimental unit assumed, and whether condition is confounded with batch. Write the estimand for the primary DE contrast."

c.2 · Critique

"As a trial biostatistician, critique SignalFold's statistics: are estimands defined, is multiplicity controlled at the right family level, is the experimental unit correct for stage-3 enrichment? What invalidates the inference?"

c.3 · Implementation thoughts

"Propose recording experimental design (conditions, batches, replicates, unit) as first-class run metadata, and using it to auto-select the DE model and multiplicity scope."

Statistician statistician Tier 2 52 sources · 247 lines

applied inference / experimental design / causal & survey methods

A method-general backstop on missing data, multiplicity, and the inference traps a multi-step pipeline invites.

(a) Skills to include — grounded

  • Handle missing data by mechanism (MCAR/MAR/MNAR) — complete-case bias assessment; method matched to mechanism. statistician/AGENTS.md › How You Work · L75 (also L61–64)
  • Match the multiplicity adjustment to the stakes — Bonferroni/Holm for few tests; BH FDR for screens. statistician/AGENTS.md › Mindset And First Principles · L25; How You Work · L77
  • Use valid post-selection inference — selecting then testing (sample splitting, selective inference after LASSO) or SEs are biased. statistician/AGENTS.md › Advanced Inference Notes · L222

  • Interpretation: FDR and intervals read with post-selection caveats attached.
  • Discovery: honest error control — neither inflated by peeking nor crippled by mismatched correction.

(c) Prompts for the next pass

c.1 · Explore & investigate

Network Scientist network-scientist Tier 2 added 48 sources · 220 lines

graph theory / community detection / generative models (SBM, ERGM) / null-model inference

The graph-theoretic rigor behind the stage-1 co-expression step — systems-biologist frames the biology, network-scientist supplies the community-detection and null-model discipline.

(a) Skills to include — grounded

  • Community detection is ill-posed — algorithms optimize different objectives (modularity, conductance); the module partition isn't unique, and modularity has a resolution bias. network-scientist/AGENTS.md › Mindset And First Principles · L16

(b) What it enhances

  • Representation: modules carried with the detection objective and resolution used, plus a degree/weight-preserving null comparison.
  • Interpretation: a module is read as one of many possible partitions, not the partition; hub claims survive a GoF test.
  • Discovery: distinguishes genuinely robust modules/hubs from artifacts of the clustering choice or a correlation threshold.

(c) Prompts for the next pass

c.1 · Explore & investigate

"For the stage-1 co-expression modules, identify the community-detection objective and resolution used, and test partition stability across algorithms/seeds. Do any 'hub' or 'scale-free' claims survive a CSN goodness-of-fit test?"

"As a network scientist, critique the module detection: is the partition treated as unique, is modularity's resolution limit acknowledged, are modules compared to a degree-preserving null?"

c.3 · Implementation thoughts

"Propose reporting the detection objective + resolution and a degree-preserving null comparison alongside each module, and replacing any bare 'scale-free' claim with a GoF result."

11. How skills run today in k-dense-byok

Grounded in the engine source at /Users/sdev/Dev/projects/k-dense-byok. The engine ("Kady", built on the Pi coding agent) runs one agent per project inside a per-project uv sandbox, and a skill's Python script is ultimately just a bash command that calls uv run.

  • Builtin tools. The Pi agent's tool set is ["read","bash","edit","write","grep","find","ls"] (server/src/agent/tools.ts:9). The bash implementation lives in the external @earendil-works/pi-coding-agent package (not vendored here), but every session is pinned to cwd: paths.sandbox (server/src/agent/session-registry.ts:103) — so all skill scripts run with the project sandbox as CWD.
  • Skill seeding. Skills are copied from K-Dense-AI/scientific-agent-skills (subpath skills, branch main; server/src/agent/skills.ts:20-22) into sandbox/.pi/skills/ (server/src/projects.ts:122) via a shallow git clone --depth 1 or a sibling-project copy (skills.ts:45-74); each dir with a SKILL.md is copied recursively, so scripts/ comes along. Pi auto-discovers and activates them natively.
  • The uv sandbox. Each project gets a uv-managed Python project — seedSandboxFiles() writes a pyproject.toml (numpy/pandas/matplotlib/scipy, requires-python >=3.11) and the venv lives at sandbox/.venv/, pre-warmed by uv sync (server/src/sandbox-seed.ts:18-101). The injected AGENTS.md mandates uv run python script.py and uv add <pkg>, never bare python/pip (sandbox-seed.ts:41-47) — the same uv-only discipline this machine enforces.
  • Web + MCP + subagents. Web tools (web_search/code_search/fetch_content/get_search_content over Exa/Perplexity/Gemini) come from pi-web-access (web-access-bridge.ts:36-41); MCP servers are dialed and each tool wrapped as mcp__<server>__<tool> (mcp.ts:90-151); heavy work fans out to 23 scientific subagent personas running as child pi CLI processes (subagents.ts:34-263).
  • The registries. web/src/data/databases.json is a registry of 229 real APIs (e.g. api.nasa.gov, arXiv, ADS); web/src/data/workflows.json holds 326 fill-in-the-blank prompt templates (e.g. write-paper with a {topic} placeholder + suggested skills).
  • Provenance. session-export.ts:104-146 replays every bash tool call from the session JSONL into a set -euo pipefail re-runnable session-<id>.sh (served at GET /sessions/:id/export?format=sh) — non-bash steps become comments, so the script is a faithful audit trail.
  • Model calls. Routed to OpenRouter (openrouter.ai/api/v1) or local Ollama only (server/src/agent/models.ts:128-144).
Mechanism in one breath. A (often workflow-templated) prompt hits a Pi AgentSession pinned to the uv sandbox → the agent activates a seeded skill from sandbox/.pi/skills/ → invokes its script through the bash tool → which runs uv run inside sandbox/.venv (deps added with uv add) → results return to the agent; web/MCP tools reach the 229-API registry, subagents fan out, and session-export turns the whole run into a re-runnable bash script for reproducibility.

12. How skills could run in SignalFold

Reasoned options, all respecting the hard constraints: uv-only Python (use uv venv/ uv run, never bare python/pip); the read-only pipeline (pipeline.py, stage runners, r_scripts/ are off-limits — wire skills as new additive services/hooks, never edits); and the ssb1 branch rule. None of this is built here — it's a design menu.

OptionWhat it isFit & cost against SignalFold's constraints
A · Vendor select scriptsCopy a few deterministic, network-free scripts into a new SignalFold-side backend/services/scientific_skills/ dir and call them as post-stage helpers (e.g. scientific-visualization/figure_export for deliverable figures; exploratory-data-analysis/eda_analyzer for a run EDA report; pathway-enrichment/run_enrichment with a local GMT to enrich a hit list).Lowest cost, highest fit. Tools run server-side; outputs still pass through security.py's scrubber, preserving anti-exfiltration. Respect the 4-iteration cap and keep network scripts behind external_lookups' cache→quota→circuit-breaker.

Recommendation. Start with A — vendor 2–3 deterministic, offline scripts (figure_export, eda_analyzer, run_enrichment with a local GMT) behind a tiny uv-runner helper, deps pinned, as additive post-stage services on ssb1. Layer a lightweight B to surface them in chat once stable. Two hard rules from the audit: (1) route every network script (gget, bioservices, enrichr, pubmed) through the existing external_lookups/ safety chain rather than calling out directly; (2) exclude the AI scripts (markitdown/convert_with_ai, the *_ai schematic generators) — they call OpenRouter (Claude/Gemini), conflicting with SignalFold's Anthropic-only design and the anti-exfiltration boundary.
